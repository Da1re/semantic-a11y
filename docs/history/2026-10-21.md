- PPT(claude.ai Slides): "AI 모델 후보" 장을 연결 방식 3가지로 다시 쓰고, 테스터용 "직접 해 보기" 장을 추가했다(15장). 문제 장 색을 다른 장과 맞추고, 모든 장을 세로 가운데 정렬했다. 결과·로드맵·흐름·마무리 장의 문구와 발표자 노트를 BYOK에 맞게 고쳤다. mock 고지는 그대로 둔다

## 결정
- 키 보관: 기본은 메모리(새로고침하면 사라짐). "이 탭에 암호화해 기억하기"를 켜면 추출 불가 AES-GCM 키는 IndexedDB, 암호문은 sessionStorage에 둔다(탭을 닫으면 지워짐). 같은 사이트의 스크립트(XSS)까지 막지는 못한다는 점을 화면에 적었다
- 키는 queryKey·내보내기·콘솔·오류 문구에 넣지 않는다. 점검하기를 누를 때 제공자·모델·이미지 여부만 점검 대상(`AuditTarget.llm`)에 묶어 queryKey로 쓴다. 연결을 나중에 바꿔도 본 결과가 저절로 다시 판정(과금)되지 않는다
- 웹 제공자는 Anthropic만. OpenAI는 브라우저에서 보내는 POST(Authorization 헤더)를 CORS로 막는다(배포 주소의 크롬에서 가짜 키로 확인. GET은 열려 있고 POST만 막힘). OpenAI 어댑터는 2단계 CLI(Node)에서 쓰려고 남겨 둔다
- 기본 모델 `claude-sonnet-5-5`(10/21 공식 모델 목록에서 이미지 입력·구조화 출력 지원 확인). 목록: sonnet(기본)·haiku·opus, 다른 id는 직접 입력
- 스키마는 두 제공자 엄격 모드가 함께 받는 기능만 쓴다. null 합집합 대신 `severity: 'none'`·빈 `fix`로 받고, 범위·존재 여부는 검증기가 본다(설계 문서의 nullable 초안에서 바꿈)
- 검증기는 직접 쓴 가드 함수(의존성 없음). 후보에 없는 선택자, 요소 하나를 가리키지 않는 선택자, 기준표에 없는 KWCAG, 0~1 밖 신뢰도, 위반인데 심각도·근거 없음은 버린다. `fix.before`가 페이지에 한 번만 나오지 않으면 판정은 두고 수정 코드만 버린다. 같은 선택자+항목은 신뢰도 높은 쪽만
- 이미지 전송은 기본 켬. 끄면 경고를 보이고, 이미지를 못 본 5.1.1 판정은 신뢰도를 0.69로 낮춰 사람 확인으로 보낸다
- 후보 150개를 넘으면 보내지 않고 알린다(나눠 보내기는 다음 단계). 설계의 "40개 넘으면 나눠 보내기"는 미룸
- AI 연결로 점검한 결과에서는 "수정 코드 적용·재점검"을 숨기고 안내만 한다(수정 목록과 재점검 판정이 mock 파일에 묶여 있어서)
- 검수 대기열 페이지는 mock 판정만 모은다(키를 그 페이지로 들고 가지 않는다)
- 기준서·어댑터는 AI를 연결한 사람만 쓰므로 지연 로드한다(`llm-judge` 청크 약 18KB)

## 검증
- `pnpm typecheck`·`lint`·`build` 통과
- 1단계 기준: mock 판정 32건·규칙 수정 11건을 검증기에 넣으면 전부 통과, 일부러 틀린 항목 10건(판정 9·규칙 수정 1)은 7건 거절(이유 포함), 같은 요소·항목 2건은 신뢰도 높은 1건만 남고, 1건은 수정 코드만 제외. 정답 라벨의 AI 선택자는 모두 후보에 들어간다(shop 49·signup 23·notice 34개 전송)
- 제공자 응답을 Playwright route로 바꿔 끼운 화면 흐름: 연결 → shop 점검(이미지 8장), JSON 내보내기에 키 없음, sessionStorage에 평문 키 없음, 새로고침 후 복원, 401 문구, 오류 뒤 자동 재호출 0건·다시 시도 1건, 키를 고친 뒤 점검하기 재실행, 비전 끔이면 이미지 0장·5.1.1 사람 확인
- 키를 연결하지 않은 mock 흐름은 그대로: 정답 대비 규칙·AI 모두 맞음, 수정 적용 13→0, 검수 대기열 3건
- 실제 Anthropic API에 가짜 키: 브라우저에서 401을 읽음(CORS 열림). 실제 키로는 아직 돌려 보지 않음
- 자기 점검 axe 위반 0건(연결 폼·직접 입력·연결됨·AI 결과 화면)
